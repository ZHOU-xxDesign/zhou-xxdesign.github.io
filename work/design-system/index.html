Magic Design System 1.0

一套从设计 token 一路搭到组件库的完整体系。目标是让机器人产品的多端界面， 在多人协作下依然保持一致的视觉与交互语言。

Time
2026
Role
UI/UX 设计师
Scope
设计系统 / 组件库
Output
全局属性 · 素材库 · 组件库

Structure体系分层

整套系统分三层推进：最底层是全局属性（不可再拆的最小单元）， 中间是素材库（图标与插画），最上层是通用组件。 上层只引用下层的变量，改一处全局生效。

01全局属性

设计中的最小单元，无法被拆解。

Color

色彩规范

品牌色 / 辅助色 / 系统色 / 字体色 / 背景色 / 功能色，六类角色各自独立，避免混用。

Type

字体规范

displayLarge 64 / displayMedium 48 / headlineLarge 36 / headlineMedium 28 / headlineSmall 24，及各级 title / body / label。

Space

间距

以 Unit 4 为基数：XS 8 / S 12 / M 16 / L 24 / XL 32 / XXL 48。卡片与分区间距按信息层级递增。

Radius

圆角

3px 极小圆角、8px 常规圆角、30px 卡片圆角、10px 图标圆角，另有胶囊与圆形两种特殊形态。

Shadow

阴影

基础投影 / 中级投影 / 上级投影三档，用模糊半径与不透明度区分层级，不用颜色区分。

02素材库

Icon 一致性

定义 32×32 作为图标的基础绘制尺寸，需要其他尺寸时等比缩放，避免逐尺寸重绘导致的粗细不一。 风格上以圆性图标为主、线性图标为辅。

通用图标采用线性风格，线条粗细统一为 2.5px。动作图标单独定义为 40×40， 因为需要承载更复杂的人体姿态信息。

动作图标：用关节定位姿态

机器人动作图标是这套素材库里最有挑战的部分。做法是用圆圈定位关节， 再基于关节绘制不同状态的动作，从而尽可能准确地表达机器人的姿态—— 这也让图标与机器人本体的动作形成映射关系，用户看图即知机器人会做什么。

覆盖举手、左右飞吻、鼓掌、剪刀、翻跟头、拳击、俯卧撑、马步推掌、依次翻滚、侧压腿等数十个动作。

03通用组件

最小单元的组合呈现，赋有特殊功能。覆盖按钮、输入框、搜索框、选择器、下拉菜单、开关、提示框七类。

每一类都按三个维度定义：Type（组件类型）、Status（组件状态，如默认 / 禁用 / 加载中 / 悬停 / 点击）、 Style（组件样式与尺寸）。这样开发在实现时能直接对应到状态矩阵，而不是只拿到一张静态稿。
