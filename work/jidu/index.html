Context项目背景

集度数字座舱（JIDU Digital Cockpit）是整车智能座舱的交互界面。 我负责其中导航与地图相关的部分：从首页的快捷入口、搜索、POI 详情、算路，到导航中的行程面板， 以及地图本身的绘制规范。

工作方式是独立负责 2D 导航项目的 UI 界面与地图配置，输出 UI 界面 400+， 并参与 3D 地图的部分设计。过程中积极且及时与开发沟通问题， 最终上线还原度达到 98%。

Flow主流程设计

首页

快捷指令操作区承载搜索、家、公司三个高频入口，其中家与公司支持自动通勤导航。 首页 icon 可直接快速进入导航界面。

搜索

搜索结果列表展示目的地名称与距离信息。POI 展示目的地相关信息，推荐 POI 带有首选的 icon 展示。 右侧面板区域的扎点，直观展示目的地距离当前位置的相对距离。列表化直观展示下方数据源，滑动查看更多信息。

POI 详情

用三色标签区分信息类型：智驾标签代表智能驾舱的地点，用品牌色承载； 重要标签如距离、营业时间等；普通标签为目的地的一般信息。 双色小标展示目的地多个出口的信息，下方可把此 POI 设置为途经点或终点。

收藏 icon 点击有动效展示，增加趣味性，也保持整体系统动效的一致性。 POI 的终点信息以及到达电量信息多用图形化表达，减少用户阅读信息的疲劳感。

Navigation导航与语音

算路策略

最终推送 3 条最优算路结果，倒计时 8 秒后默认以第一条作为最佳路线开始导航。 筛选项包括智能推荐、智驾优先、避免拥堵、时间短、少收费、不走高速、高速优先。

导航中

3D 区域展示红绿灯信息，红灯增加了动效设计，设计上也更符合现实。 行程面板展示整段路程的途经点和目的地信息：下一个途经点做高亮显示，走过的途经点置灰显示， 终点距离信息和预计到达时间进行轮播。最下方 icon 可以展开或收起整个面板并显示最近途经点 / 终点信息， 也可结束整个导航行程。

4D 区域显示下一个 TBT 信息：里程数、行驶方向、出口信息。

语音大模型

将 AI 能力（文心一言）赋予语音原子卡，品牌色沿用智驾的紫色—— 让 AI 能力在视觉上有独立且可识别的身份。

Thinking地图设计思考

系统性分析地图绘制的要求和逻辑。

车机地图和普通 App 地图不一样：它是在驾驶场景下被扫一眼就要读懂的信息类工具。 我把它拆成四个问题来回答。

01 · 基础认知

符合制图学和公众认知：地图发展到现在已经成了一门学科， 即便语言不通，拿到一张地图也能看懂——这是因为有制图学和公众认知在规范着地图设计。 比如地图默认北向上、草地水系基本遵循物理世界的颜色、省界线是实线、停车场图标大多用 P 来代表。 符合这些约定，能大大降低用户的学习成本和记忆负担。

保证识别度：地图属于信息类工具，其上出现的元素均需清晰可识别， 保证可读性是最基本的设计原则，所以在设计时会限制颜色对比度、最小字号等，具体规则会根据场景确定。

清晰有层次：信息主次清晰，地图信息庞杂，要做到同类元素有关联性，不同元素有差异性。 同时信息主次也会根据比例尺的变化有所调整。 在业务场景中，地图通常作为最底层组件出现，上层还会有很多业务组件， 因此在设计时需克制用色——既要保证地图中各类元素之间的区隔度，又要保证地图整体与其他业务组件拉开视觉层级。

02 · 拆解地图

将地图拆分为基础层、策略层和感官层，帮助各职能角色找到对应切入点。

基础层

数据与能力

引擎渲染能力、定位能力、图像识别能力等。有了数据及各类能力作为基础，才能设计出信息精准、交互明确的地图。

策略层

如何使用这些能力

地图数据量非常庞大，无法全部展示，需要结合不同的场景及用户需求，有重点地呈现。

感官层

最终视觉呈现

根据品牌调性、对应场景诉求等去设计最终的配色、图标等。

03 · 元素显示策略

将地图元素详细拆分，更有利于分析每个元素的显示策略——分为面元素、线元素、点元素三类。

道路显示策略按比例尺分层：3–9 层级（2000km–25km）时只聚焦到每个城市和县区名称， 这一层级下的道路显示感知度不高；10–12 层级（20km–5km）道路层级显示为一级道路， 默认百度 / 高德本身的显示策略比较合适，显示比较清晰； 13–17 层级（2km–100m）一、二、三级道路都会显示， 因此层级的显示策略会对地图的整体性有较大影响，需要谨慎选择显示比例尺。

此外还有蚯蚓线（用颜色与线宽区分主路与备选路）、点元素（车标、POI、扎点、气泡）等元素的独立策略。
